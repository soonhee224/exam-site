options:
  - "101000110101110"
  - "101000110111001"
  - "101000110101101"
  - "101000110110110"
explanation: |
  1단계: 나눗셈을 위한 메시지 비트 확장
  • 생성 다항식(나눗수) $P = 110101$의 비트 수는 6개이므로 차수는 $k = 5$입니다.
  • 메시지 $D = 1010001101$ 뒤에 0을 5개 덧붙여 피제수 $D'$를 만듭니다:
    $$D' = 101000110100000$$

  2단계: 모듈로-2(XOR) 나눗셈을 통한 FCS(나머지) 산출
  • $101000110100000$을 $110101$로 모듈로-2 나눗셈을 단계별로 수행합니다:
    - $101000 \oplus 110101 = 011101$
    - $111011 \oplus 110101 = 001110$
    - $111010 \oplus 110101 = 001111$
    - $111100 \oplus 110101 = 001001$
    - $100100 \oplus 110101 = 010001$
    - $100010 \oplus 110101 = 010111$
    - 마지막 5비트 나머지: $01110$
  • 따라서 전송 부호 $T$는 원래 메시지 뒤에 나머지 $01110$을 덧붙인 $101000110101110$이 됩니다.

  최종 결과:
  • 올바른 부호 $T$는 ①번(101000110101110)입니다.

순회 잔여 검사 부호(Cyclic Redundancy Check(CRC) Code)에서 메시지 $D = 1010001101$이고 나눗수 $P = 110101$일 때 전송되는 부호 $T$로 가장 옳은 것은?
